# Direct Cloudflare Builds deployment

The signer owns its production release. Cloudflare Workers Builds uses the installed `susanbeasles/signer` GitHub repository connection, source repository ID `1416201242`, and the `main` production branch. No GitHub dispatch token, Github App private key or signing service token goes into the GitHub workflow. The `.github/workflows/deploy.yml` job performs credential-free source validation only.

Configure the Cloudflare production build trigger for Worker `signing-control` and the approved dedicated build token. Keep build caching disabled and preview deployments disabled (the signer has no public routes). Set `root_directory` to `/`, `branch_includes` to `["main"]`, build command to `npm ci --ignore-scripts --no-audit --no-fund && npm test`, and deploy command to `node deployment/deploy.mjs`. Cloudflare must provide its standard `WORKERS_CI`, `WORKERS_CI_BRANCH`, `WORKERS_CI_COMMIT_SHA`, and `CLOUDFLARE_API_TOKEN` build variables. Supply the reviewed public `SIGNING_DEPLOYMENT_JSON` as a build variable. The source's verified signed current-main SHA is independently checked against GitHub twice. No credentials are needed for public GitHub readbacks.

The operator-approved `SIGNING_DEPLOYMENT_JSON` contains only immutable public image/tool hashes, pinned signing public-key/item metadata, exact private service bindings and a `signerTokenSecret` reference (`store_id`, `secret_name`). The actual 1Password service-account token must already be present as an **active Workers-scoped secret in Cloudflare Secrets Store**, never in GitHub or the build environment. The Worker receives it only through native `SIGNER_SERVICE_ACCOUNT_TOKEN` binding. `SOURCE_POLICY` must be an independently commissioned private Worker service capability. Missing metadata, unsigned/stale source, unapproved images or keys, absent private bindings or a mismatched existing Worker fail closed.

Initial provisioning may target either an absent Worker or an inert `ENABLED=false` bootstrap Worker having only the two exact disabled public vars. No public routes/workers.dev/preview URL or raw signing endpoint are enabled. Existing active Workers require a matching native Secrets Store binding; the deployer will not silently migrate legacy token custody. A first Worker/bootstrap creation and immutable Container image publication require independent live provider readback and security qualification. This source does not invent a public key, private credential, build token, approved producer, image digest or source policy.

The Cloudflare repository connection is established; token creation, the Worker/Container and production trigger cannot be treated as commissioned until their exact permissions and resource state are confirmed. The central `deployer` system remains separate and cannot be used as an unreviewed signer bootstrap substitute.
