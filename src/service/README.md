# Dedicated source signing service

`run.mjs` is the production composition used by the fixed container supervisor. It imports the pinned local runtime directly; no request may choose a signer, executable, policy module, provider endpoint, or generic signing bytes. `src/vendor/repoctl/provenance.json` records exact reviewed local source hashes, and labels that source as uncommitted rather than inventing a publication SHA.

The Cloudflare controller owns durable metadata and serializes one action per configured repository. The service uses revision CAS with no retry. Candidate signing and the two owner-approved tag signatures each consume a separate retained signing effect before the runtime can read the dedicated 1Password item. Hardware approval, CI, complete scans, independent review, source policy, and publication remain separate installed private capabilities. Absent capabilities deny execution; a configuration flag is not evidence.

The public runtime configuration is `{service,runtime,platform}`. `service` contains `schema:'signing-control-service/v1'`, numeric `repositoryID`, exact `repository`, the fixed `git` executable/path/digest/limits, and `signer:{keyID}`. `runtime` is the op-agent configuration; `platform` identifies the Cloudflare image digest. The canonical SHA256 of these exact bytes is the job's `configDigest`. A job has `{version:1,id,action,input,configDigest,deadline}`; its deadline is at most 300 seconds away. Runtime/controller validation remains mandatory even when a bootstrap artifact is disabled.

`prepare` still requires an existing source PR and constructs the reviewed main-parent promotion candidate. The original owner, validator, and final main-writer authorities are unchanged. `publishShadow` and `publish` use the fixed standalone publisher; `PublicationAuthority.verify` consumes the exact already-retained publication grant. The signer runtime receives no GitHub write credential.

`prepareFeature` accepts exactly `{repositoryID,baseSHA,treeSHA,featureRef,message,author,committer,nonce,expiresAt}`. Only `refs/heads/feat/...`, `refs/heads/fix/...`, and `refs/heads/feature/...` are structurally eligible. The shared `feature-contract.mjs` reconstructs a single-parent unsigned commit with the fixed header order, rejects unknown fields and malformed text, and hashes the exact bytes. It has no local Git/tree dependency. The tree hash is explicitly the authenticated producer's claim, not evidence of content inspection or code safety.

The source-owned workflow_depot producer policy admits the exact request and returns `{authorized:true,requestDigest,policyDigest,signerKeyID,producerID,producerEvidenceDigest,grantID,expiresAt}`. `SOURCE_POLICY.authorizeFeatureCommit(request)` reads that retained grant; the runtime reserves `signingConsumed` durably, then `consumeFeatureCommit({request,grantID})` consumes it once before key access. The returned grant must match every retained field. After signature verification, `checkFeatureCommit({request,grantID})` must confirm the same consumed grant under current policy, producer and parent/ref checks. Neither later replies nor retries can extend the original lifetime. A missing producer identity, policy change, expiry, replay, or ambiguous consume/signature fails closed.

`prepareFeature` returns `{receipt,signature}`. Its receipt explicitly states `claim:'authenticated-producer-intent'`, binds the producer/evidence/grant identifiers, canonical payload digest and signed Git object hash, and contains no `complete` or `closureDigest` assertion. `lookupFeature({repositoryID,nonce})` privately returns `{receipt,signedCommit}` only after reconstructing the exact request and checking the retained receipt, Git object hash and pinned signature. The separately authorized producer can assemble/import those exact commit metadata bytes locally, verify the pinned signature and object hash, verify its actual parent/tree objects, and publish only through its existing normal Git authority. The signer receives no GitHub write credential.

Feature signing is automatic under accepted depot policy; it does not require a per-feature owner prompt. Its live prerequisites are the authenticated producer admission, exact private depot grants, the qualified Cloudflare runtime, and the dedicated configured signer. CI/scans/review/hardware/publisher/history capabilities are still required by their respective promotion operations; they are not feature-signing prerequisites.

Signed commit/tag metadata is a narrow allowed RPC exception: bounded headers, commit/tag message, and signature tied to the retained generation. The adapter and controller reject blob/tree types, unknown callback shapes and unrelated metadata. Actual source acquisition uses only the fixed GitHub HTTPS repository through normal Git, with redirects/helpers/hooks disabled and separately scoped read authority when required. `maxBytes` bounds the inspected/retained object closure; it is **not a network download-byte limit**. Fetch has a deadline; a commissioned host must separately impose disk/resource limits.

Promotion history requires an independently accepted `SOURCE_POLICY.current().historyCustody` record with exact `{schema:'signing-control-history-custody/v1',mountPoint:'/var/lib/signing-control/history',device,mountSource,filesystem}`. The dedicated mounted filesystem must match that identity in `/proc/self/mountinfo`; existing directory permissions, filesystem kind, exclusive creation, no-follow readback, content digest and file/directory fsync are also checked. Merely creating an ext4 directory is insufficient. The default disposable Cloudflare image has no such qualified mount and therefore cannot claim durable retained history. There is no ephemeral-memory fallback and no source-archive RPC route. This remaining custody prerequisite is distinct from commissioning the dedicated signer.

Tests use synthetic producer grants and policy/evidence/signatures; source acquisition tests separately use local Git fixtures. They prove composition, rejection, replay and cleanup behavior; they do not prove commissioned keys, real hardware provenance, live GitHub permissions, durable provider storage, or a completed remote publication.
